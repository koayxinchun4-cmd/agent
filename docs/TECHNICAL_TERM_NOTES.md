# Technical Term Notes

## Purpose

When explaining technical, scientific, programming, Android, AI, or engineering concepts, automatically add a short beginner-friendly note when a technical term first appears.

This is a project communication and documentation convention for Nexus development.

## Format

Use:

**Technical Name — 中文 meaning / short explanation**

Keep the explanation short and practical. English remains the primary learning language; Chinese is only there to make the term immediately understandable.

## Examples

- **Kotlin — 编程语言：used to develop Android apps**
- **API — 接口：lets different software systems communicate**
- **Agent — 智能代理：understands a task and performs actions**
- **Repository — 代码仓库：stores project code and its history**
- **CI — 持续整合：automatically checks and tests changes**
- **Gradle — 构建工具：handles build configuration, dependencies, and packaging**
- **Jetpack Compose — Android UI 工具：used to build Android interfaces**
- **Binary — 二进制：a number system using `0` and `1`**
- **Blob — 文件内容对象：a Git object that stores file contents**
- **Tree — 目录结构对象：a Git object that records paths and entries**
- **Commit — 提交版本：a recorded version of the repository state**

## Rules

1. Explain a professional term automatically the first time it appears.
2. After a term has been explained, it can be used directly later.
3. Keep explanations short and suitable for a programming beginner.
4. Do not change the original English technical name.
5. Do not explain every ordinary English word.
6. Science names and technical names are both covered.
7. If a term is obvious from context, a very short explanation is enough.
8. If the user asks "what is this?", provide a more detailed explanation.
9. For code, architecture, Android, AI, networking, GitHub, science, or engineering concepts, prefer this format.
10. This is a communication and documentation convention; it does not require comments beside every symbol in source code.

## Language

- **English-first** for technical learning, documentation, and self-study.
- Keep the original English technical term so it can be searched directly in official documentation and other English resources.
- Add a short Traditional Chinese meaning/explanation only when it helps the learner understand the term.
- Do not turn technical explanations into Chinese-first translations unless the user explicitly asks for a Chinese explanation.

## Goal

The project owner is self-learning through building Nexus. The documentation should therefore preserve professional English terminology while giving just enough Chinese support to remove vocabulary barriers.
